## 8. User-Provided References

References are optional. No references is a valid Phase 1 outcome.

| ID | Type | Source / Location | User's description | Intended relevance | Analysis status |
|---|---|---|---|---|---|
| REF-01 | Website / GitHub / Document / Screenshot / App / Notes / Other | | | | NOT YET ANALYZED |

Reference handling rules:

- Preserve the reference exactly enough for later retrieval or identification.
- Preserve the user's reason for providing it.
- Record intended relevance without turning it into a requirement.
- GitHub repositories use this same reference model; there is no separate GitHub subsystem.
- User-provided references are evidence of user interest or context, not proof of market demand, competitor status, feasibility, technical suitability, legal status, or product correctness.
- Full market, competitor, feasibility, technical, legal, and validation analysis belongs to later lifecycle stages.
